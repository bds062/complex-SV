# Software environment

## Recommended installation

The supplied `environment.yml` creates an environment named `complex-SV`:

```bash
conda env create --file environment.yml
conda activate complex-SV
python workflow/00_check_install.py
```

Mamba can resolve the same file more quickly:

```bash
mamba env create --file environment.yml
conda activate complex-SV
python workflow/00_check_install.py
```

The YAML uses Python 3.11 and retains the channels and package family from the
Severus environment. It adds the numerical, tabular, machine-learning, and
graph-learning packages required by complex-SV. PyTorch and PyTorch Geometric
are installed through pip inside the Conda environment because current PyTorch
releases are distributed as wheels rather than through the official PyTorch
Conda channel.

The default PyTorch wheel is intended to be portable. On a GPU cluster, check
the resulting build before launching training:

```bash
python - <<'PY'
import torch
import torch_geometric

print("PyTorch:", torch.__version__)
print("PyG:", torch_geometric.__version__)
print("CUDA runtime:", torch.version.cuda)
print("CUDA available:", torch.cuda.is_available())
PY
```

If the wheel does not match the cluster CUDA driver, install the appropriate
PyTorch wheel using the command generated by the official PyTorch installation
selector, then rerun `python workflow/00_check_install.py`. The models can also
run on CPU by passing `--device cpu`, although training and embedding are much
slower.

## Can the Severus environment be reused?

Yes, technically. complex-SV consumes Severus VCF output and its Python
requirements are compatible with the package family in the Severus environment.
The supplied YAML is intentionally a superset of Severus's environment file.
An existing environment can be extended without pruning it:

```bash
conda activate severus_env
conda env update --name severus_env --file environment.yml
python workflow/00_check_install.py
severus --help
```

Do not add `--prune`: the complex-SV YAML specifies Severus dependencies but
does not install the `severus` executable itself, so pruning could remove an
existing editable or packaged Severus installation.

A separate `complex-SV` environment is recommended for publication
reproducibility. It isolates the large PyTorch stack from the SV-calling
environment, avoids changing a validated Severus installation, and is sufficient
because the two stages communicate through VCF files. Reusing `severus_env` is
reasonable when storage is constrained and both `severus --help` and the
complex-SV installation check pass afterward.

## Installing Severus in the complex-SV environment

The reverse arrangement is also possible. After creating `complex-SV`, install
Severus from Bioconda or its source checkout:

```bash
conda activate complex-SV
conda install --channel bioconda severus
severus --help
python workflow/00_check_install.py
```

This is convenient for a single end-to-end calling environment, but the
reported complex-SV models require only the resulting Severus VCF—not the
Severus executable at inference time.
